# 작성 프로필 — 반복되는 개인 선호를 공개 규칙과 분리하기

같은 사용자가 지원서마다 같은 교정을 반복한다면 그 선호를 매번 대화로 다시 설명하게 하지 않는다. 반대로 한 사람의 문체·구조 선호를 이 스킬의 보편 규칙으로 올리지도 않는다. 둘 사이를 잇는 것이 작성 프로필이다. 프로필은 사용자가 소유한 개인 자료이며 이 저장소나 공개 배포본에 넣지 않는다.

## 찾는 순서

전체 작성·수정·평가를 시작할 때 한 번 찾고, 찾은 위치를 작업 기록에 남긴다.

1. 현재 요청이나 대화에서 사용자가 지정한 파일·Notion 페이지
2. 사용자 전역 지침이 가리키는 개인 작성 스킬이나 문서
3. 환경 변수 `JASOFORGE_PROFILE`이 가리키는 파일
4. `~/.jasoforge/profile.md`

없으면 기본 지침으로 진행한다. 프로필이 없다는 이유로 질문을 늘리지 않는다.

## 담을 수 있는 것

- 문체와 구조 선택: 소제목 사용 여부, 끝 문단의 형식, 지원동기 전개 방식, 피할 표현
- 기계로 확인할 수 있는 문체 규칙: 금지 문자, 문장당 쉼표 상한, 주의할 표현 패턴
- 소재 선택: 쓰지 않을 경험과 이유, 기본 소재로 확정하지 않을 경험, 우선 검토할 경험 계열
- 참고할 본인 지원서를 찾는 방법: 예를 들어 지원 현황에서 서류 통과로 표시한 행
- 진행 선호: 로컬·Notion 기본값, 평가 전 정리 항목, 보고 방식
- 지원서 입력 선호: 임시저장을 누가 할지, 선택 항목을 어디까지 채울지

경험 사실·수치·회사 정보는 프로필에 복제하지 않는다. 그것은 경험 기록과 조사 자료의 몫이다.

## 적용 방법

- **작성**: Step 2~3에서 프로필의 구조·소재 선택을 적용한다. 현재 요청이 프로필보다 우선한다. 프로필은 사실 확인, 지어내기 금지, 공고 규격을 덮어쓰지 못한다.
- **기계 검사**: 확인 가능한 문체 규칙은 spec.json의 `style_checks`로 옮긴다. lint는 이를 WARN으로 보고하며 공식 규격 FAIL과 섞지 않는다. 금지 문자, 쉼표 상한, 소제목은 작성과 수정 범위에서 평가 패킷을 만들기 전에 고친다. 주의 표현 패턴은 문제의 증상을 잡는 경고라서 단어만 바꿔 피하지 않고 그 문장이 하는 일을 다시 본다. 원문 진단만 요청받았다면 보고만 한다.

  ```json
  "style_checks": {
    "forbid_chars": ["·"],
    "max_commas_per_sentence": 2,
    "forbid_headings": true,
    "watch_patterns": [{"pattern": "싶습니다", "label": "바람 표현"}],
    "hedge_check": true
  }
  ```

- **평가**: 프로필은 평가자에게 넘기지 않는다. 평가 패킷을 만들 때 spec.json의 `style_checks`와 프로필 경고 줄은 빠진다. HR과 TECH는 작성자의 의도를 모르는 독자로 읽어야 하며, 선택을 감점하지 말라는 지시는 평가를 작성자 쪽으로 기울이는 과적합이다. 평가자가 프로필의 선택을 지적하면 호스트가 사용자 선택으로 분류해 수정을 권하지 않고, 그 지적을 revision_log에 남긴다. 이 기록은 나중에 실제 결과와 비교해 프로필 항목을 유지할지 판단하는 자료다.

## 갱신

- 사용자가 같은 교정을 두 번 이상 하거나 '앞으로', '항상'처럼 지속 규칙으로 말하면 프로필에 추가할지 묻고, 승인받은 문장을 날짜와 계기와 함께 적는다.
- 한 지원서·한 문장에만 해당하는 선호, 평가 결과를 보고 만든 추정은 프로필에 올리지 않는다.
- 새 문항에서 어색해지는 항목은 보류하거나 범위를 좁힌다. 평가에서 반복해 지적된 선택은 실제 결과와 함께 다시 검토한다. 사용자가 철회한 항목은 지운다.
- 스킬 코드와 공개 지침을 개인 선호에 맞춰 고치지 않는다. 여러 사용자에게 공통인 원리로 확인된 것만 [변경 지침](../GUIDELINES.md)에 따라 공개 지침에 반영한다.
