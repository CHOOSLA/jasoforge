# 정식 평가·전체 실행의 5단 진단 리포트

이 형식은 전체 파이프라인 또는 평가/진단 요청에 적용한다. 문장 윤문만 요청한 경우까지 출력하지 않는다. 긴 정식 리포트는 파일에 보존하고 대화에서는 핵심을 요약할 수 있다. 사용자가 정식 리포트를 대화창에서 원하면 전부 제공한다.

머리말: 지원 법인·사업부/직무·전형, 버전/초안 해시, 실행 ID, Audit-First/From-Scratch, 로컬/Notion, 조사한 자료의 시점과 범위. 실제 조회·평가·동기화한 것과 미실행한 것을 구분한다.

## 1. 종합 판단과 점수

현재 상태와 제출 전 고쳐야 할 중요한 문제를 먼저 말한다. 규격 위반·문항 핵심 누락·핵심 주장 모순은 작성 평균에 묻히지 않게 구체적으로 설명한다. 단정할 근거가 없으면 사실 확인 필요로 구분한다.

문항별 HR 지수, TECH 지수, 가중 지수, 적용/제외 축, 상태를 제시한다. 역할별 지수는 해당 역할의 적용 축 점수 합/(5×적용 축 수)×100이며 적용 축이 없으면 N/A다. 문항별 값과 역할 평균은 grade.py의 집계 JSON을 그대로 읽는다. 호스트가 별도 계산하지 않는다. 최종 지수·상태는 실제 grade.py 결과를 그대로 사용한다. 필요하면 계산식과 평가 당시 고정한 가중치를 밝힌다. 합격 확률이나 경쟁자 대비 순위로 쓰지 않는다.

## 2. 규격 검사

문항별 실제 최소/최대와 글자·바이트 기준, 측정값, PASS/FAIL/미확인을 표로 제시한다. 문항 ID·블라인드 위반·오탈자도 구체적으로 보고한다. 린트 출력은 원문 파일을 연결한다. 기준이 미확인이면 엔진 출력의 FAIL 0을 최종 제출 규격 보증으로 바꾸지 않는다.

## 3. 문항별 HR·TECH 평가 근거

질문 원문과 요구 항목을 적고 각 역할의 작성 축 점수와 정확한 본문 인용을 연결한다. 규격 상태와 선택적 사실 대조는 작성 점수와 분리해 표시한다. 장점도 근거를 제시하며 보완점에는 독자가 이해하지 못하는 부분 또는 근거 부족 범위를 설명한다. 서로 다른 판단은 숨기지 않고 어느 문항/자료 해석이 다른지 정리한다. 종합 에이전트가 임의로 점수를 고쳐 쓰지 않는다.

## 4. 면접 후속 질문과 답변 범위

독립 TECH가 제출한 문항별 `interview`를 근거로 질문을 제공한다. 원고 인용·질문·의도·답변 범위·추가 확인 사실 또는 생략 이유를 보존한다. 호스트가 보충한 질문은 호스트 추가임을 표시하며 평가자 원문을 대체하지 않는다. 개수를 채우기 위한 공격 질문은 만들지 않는다. 질문 / 확인 의도 / 원고와 경험 기록으로 답할 수 있는 범위 / 추가 확인할 사실을 구분한다.

가능한 기술 해결책과 실제로 한 행동을 분리한다. 자료에 없는 서버 조치·측정·장애 대응을 ‘제가 했습니다’로 생성하지 않는다. 질문이 필요 없거나 근거가 부족하면 그 사유를 적는다. 강한 비판이나 면접 난도가 채용 평가 정확성을 보증하지 않는다.

채용 법인과 고객사/담당 서비스가 구별되면 기계 집계의 조직 관계 가이드와 TECH의 관련 질문도 포함한다. 확인되지 않은 위탁 관계나 조직 책임을 단정하지 않는다.

## 5. 보완·다음 행동·기록 위치

지원 조건표의 미확인·미충족 항목과 전형 일정도 연결한다.

바꿀 이유가 있는 부분, 유지해야 하는 사실/판단, 사용자에게 필요한 질문, 수정 범위와 검증 방법을 제시한다. 전체 수정 요청이면 실행한 새 버전과 실제 재평가 결과를 보고하고, 평가만 요청이면 원고를 고치지 않은 진단으로 끝낸다.

원고·spec/context·조사·린트·두 평가 JSON·세션 토큰·집계 리포트·점수 원장·수정 로그·경험 보강 위치를 연결한다. Notion은 실제 쓰기 결과를 확인한 페이지/행만 완료로 표시한다. 단순 작성 완료를 제출로 바꾸지 않는다.

평가자 호출 기록은 역할·실행 ID·모델(확인된 경우)·시각·패킷·출력 경로를 남긴다. 새 컨텍스트 호출이 없으면 독립 평가 완료라고 보고하지 않는다. 제출 원고의 출처와 실제 제출 여부를 별도로 기록한다.

## 세 결과를 구별하기

작성 점수와 작성 상태, 문항별 compliance, fact_review 및 attention_flags를 함께 출력한다. 첫 사용자의 NOT_PROVIDED는 증빙 감점이나 검토 실패가 아니다. source_kinds로 사용자 진술과 기록 대조 범위를 드러낸다. 작은 표현 정정과 중심 성과의 충돌을 구별하고 후자는 점수 앞에 명시한다.

필수 문항·직무 입력 때문에 DEFERRED가 있으면 그 문항과 전체 작성 평균은 null이다. 평가한 부분의 지적과 유보 이유는 보존한다. 핵심 사실 충돌은 PROVISIONAL_FACT_CONFLICT이며 점수만으로 원고를 확정하지 않는다. v4 총점과 v5 작성 점수의 차이를 개선량으로 설명하지 않는다.
